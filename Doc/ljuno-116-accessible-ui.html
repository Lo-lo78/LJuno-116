Overview

The LJuno-116 Lua interface is a keyboard-first, OSARA-friendly control surface designed to make the synthesizer playable and editable without depending on visual hunting.

It is not a generic utility layered on top of the instrument. It is part of the instrument’s design logic.

The interface is built around:

  • page-based navigation
  • spoken parameter feedback
  • consistent row-and-key structure
  • direct parameter selection
  • numeric editing for continuous values
  • fast reset and initialization behavior
  • preset navigation
  • preset browser with preview, search, save, rename, delete, and manual reordering
  • full patch snapshot workflow
  • context-aware warnings for waveform compatibility
  • optional integrated access to LArp from the same interface

The result is a control system that favors structure, predictability, and speed.

Automatic Loading and Track Behavior

When the script runs, it works on the currently selected track.

If LJuno-116 is already present on that track, the script attaches to it.

If LJuno-116 is not present, the script attempts to load it automatically using:

Effects/Lo-lo - JSFX/Instruments/LJuno-116/LJuno-116.jsfx

If loading succeeds, the synth is attached immediately and becomes the main target of the interface.

If no track is selected, the script stops and reports that no track is selected.

LArp is handled differently:

  • LArp is not forced at startup
  • it is loaded on demand when needed from the interface
  • the script uses: Effects/Lo-lo - JSFX/MIDI/LArp.jsfx
  • when loaded, LArp is moved to slot 0 and LJuno-116 is placed after it
  • when LArp is first loaded by the interface, it is created disabled by default

This means the interface is designed around a direct working assumption:

  • choose the track
  • launch the script
  • control the synth immediately
  • load and enable the arpeggiator only when you want it

Page Structure

The interface is organized into eleven pages.

Function keys select pages directly:

  • F1 — Osc
  • F2 — Filter
  • F3 — Env
  • F4 — LFO 1
  • F5 — LFO 2
  • F6 — EQ
  • F7 — FX
  • F8 — SuperWave L1
  • F9 — SuperWave L2
  • F10 — Global
  • F11 — Arp

The page system is fundamental to how LJuno-116 is meant to be used from the keyboard.

Each page contains a consistent grid-like mapping of parameters across rows. This allows the user to learn the instrument spatially through memory and structure, even without a visual panel.

Page announcement

You can hear the current page at any time with:

  • Backslash (\) — announce current page

If you press a page function key for the page you are already on, the page name is spoken again.

Pressing F11 loads LArp if needed and opens the Arp page.

Parameter Selection and Spoken Feedback

Selecting a parameter

Parameters are selected by pressing the assigned key on the current page.

Once selected, the parameter becomes the current target for:

  • reading
  • editing
  • stepping
  • reset
  • min/max jumps

Spoken feedback

When a parameter is selected, the script reads its label and current value.

For continuous parameters, the numeric value is spoken using the precision appropriate to that parameter.

For combo parameters, the script speaks the current item label rather than a numeric index.

Examples of special spoken behavior include:

  • Voices = 1 is spoken as Mono
  • Split Note is spoken using note names such as C4, D#3, and so on
  • Split Width = 0 is spoken as Off
  • Split Width = 1 is spoken as On
  • combo parameters always speak their textual state
  • Arp Enabled is treated as a virtual combo and speaks Off or On

Re-reading the selected parameter

  • Tab — speak current parameter name and value

If no parameter is selected, the script announces:

  • No parameter selected

Editing and Value Control

Continuous parameters

For continuous parameters:

  • Up Arrow — increase value
  • Down Arrow — decrease value

The amount of change depends on:

  • the parameter step size
  • the current step width multiplier

Large continuous steps

For continuous parameters:

  • PageUp — increase by a larger step
  • PageDown — decrease by a larger step

These use a larger jump based on the current resolution.

Combo parameters

For combo parameters:

  • Up Arrow — next item
  • Down Arrow — previous item

Combo parameters speak their item label rather than a number.

Smart min/max

For the currently selected parameter:

  • Home — jump to minimum
  • End — jump to maximum

Behavior:

  • continuous parameters jump to numeric minimum or maximum
  • combo parameters jump to first or last item and speak the corresponding label
  • for Arp Enabled, Home forces Off and End forces On

Numeric edit mode

Numeric editing is available for continuous parameters only.

  • Enter — enter numeric edit mode
  • 0–9, ., - — input characters
  • Backspace — delete last character
  • Up Arrow — speak full numeric buffer
  • Tab — speak full numeric buffer
  • Enter — apply typed value
  • Esc — cancel numeric edit mode

When a numeric value is applied, it is clamped to the legal range of that parameter.

While numeric edit mode is active, other keyboard input is blocked so the edit process remains predictable.

Step Width and Resolution

The script includes a persistent step-width system so parameter editing can be either fine or coarse.

Available step widths:

  • 1
  • 5
  • 10
  • 15
  • 20

These widths affect continuous parameter stepping.

This means the same parameter can be adjusted:

  • very precisely for delicate tuning
  • more broadly for quick movement

The selected step width is stored via REAPER ExtState, so the preferred resolution can persist between script uses.

Reset, Init, and Presets

Reset selected parameter

  • Backspace — reset selected parameter to its stored init value

Behavior:

  • continuous parameters speak the restored numeric value
  • combo parameters speak the restored label
  • if the current target is Arp Enabled, Backspace turns it Off

This reset uses the internal init tables stored in the Lua script.

Full initialization

  • Delete — apply full synth initialization

This resets all mapped LJuno-116 parameters to the stored defaults from the script and announces:

  • Init

If LArp is loaded, its mapped parameters are also restored to their stored defaults and the arpeggiator is disabled.

Preset navigation

  • + — next preset
  • - — previous preset

If the synth provides a preset name, the script announces the preset number and name.

Preset Browser and Patch Snapshots

Full patch snapshots

The interface can copy and paste a full patch state, not only the currently selected parameter.

  • Ctrl+C — capture the current full patch snapshot
  • Ctrl+V — apply the most recent valid full patch snapshot

The snapshot includes:

  • all mapped LJuno-116 parameters
  • LArp enabled state
  • all mapped LArp parameters when LArp is loaded

The snapshot is stored internally, written to ExtState, and also sent to the system clipboard when available.

This means you can use it both as an internal restore mechanism and as a transferable patch text representation.

Preset browser

  • Insert — open preset browser

The browser works with text preset files stored in:

Scripts/Lo-lo - Scripts/Instruments/LJuno-116/Presets

Preset order is now persistent. The browser keeps a dedicated order index, so manually rearranged presets stay in that order across sessions. New presets are added to the order automatically.

Entries without an existing order position are placed after the ordered ones. Their fallback ordering is based on saved time, oldest first when that information is available.

Browser core navigation

  • Up Arrow — previous preset entry
  • Down Arrow — next preset entry
  • PageUp — move by browser page step backward
  • PageDown — move by browser page step forward
  • Left Arrow — decrease browser page step
  • Right Arrow — increase browser page step
  • Home — jump to end of list
  • End — jump to start of list
  • Tab — speak current browser position and entry
  • Backslash (\) — speak browser context
  • Esc — close browser and return to the synth UI

The browser page step values are:

  • 5
  • 10
  • 15
  • 20

When you move through entries in normal browsing mode, the selected preset is preview-loaded immediately.

Browser move mode

The browser now has a dedicated reorder mode for manually arranging presets.

To move a preset, first select it in the list, then press Enter. This does not load the preset. Instead, it marks the current preset as the one you want to reposition and switches the browser into move mode.

When move mode is active, the browser announces that the selected preset is in move mode. From that moment:

  • Up Arrow — moves the selected preset one position upward in the saved order
  • Down Arrow — moves the selected preset one position downward in the saved order
  • PageUp — moves the selected preset upward by the current browser page step
  • PageDown — moves the selected preset downward by the current browser page step
  • Home — repeatedly moves the selected preset toward one end of the ordered list according to the current browser logic
  • End — repeatedly moves the selected preset toward the opposite end according to the current browser logic
  • Enter — exits move mode for the currently selected preset
  • Esc — leaves move mode without closing the browser
  • Tab — speaks current position, preset name, and whether move mode is active

So the workflow is:

  1. move to the preset you want to reorder
  2. press Enter to arm that preset for movement
  3. use Up or Down to push it higher or lower in the preset order
  4. press Enter again, or Esc, to leave move mode

After each movement, the preset remains selected in its new position. The new browser order is saved persistently.

Browser edit actions

  • Ctrl+S — save the current patch as a preset
  • F2 — rename selected preset
  • F3 — search presets
  • Delete — delete selected preset with confirmation

Enter is no longer a preset-load command inside the browser. Preview loading happens automatically while browsing. Enter is now dedicated to starting or ending preset movement.

Browser search

The search system works as a text entry mode inside the browser.

Search text editing supports:

  • Enter — confirm search
  • Esc — cancel
  • Backspace — delete previous character
  • Delete — delete current character
  • Left Arrow — move left in text
  • Right Arrow — move right in text
  • Home — move to end of text buffer
  • End — move to start of text buffer
  • Backslash (\) — clear the whole text buffer
  • Tab — speak the full text buffer

When search is confirmed, matching results are shown as a dedicated result list.

In search-results mode:

  • Esc returns to the full preset list when move mode is not active
  • Enter toggles move mode for the selected search result
  • moving through results previews the selected result immediately

Save, rename, and delete behavior

Save and rename both use the same internal text-entry engine. Invalid characters are sanitized automatically for filenames.

Renaming preserves the preset’s manual browser position when possible. Deleting removes the preset from the stored order index as well as from disk.

Delete is protected by a dedicated confirmation state with:

  • Left / Up / End — No
  • Right / Down / Home — Yes
  • Y — Yes
  • N — No
  • Enter — confirm current Yes / No choice
  • Esc — cancel delete confirmation

Wave Compatibility Warnings

Some parameters depend on the currently selected waveform family.

If you select a parameter whose behavior depends on a compatible wave family, the interface can warn you when the current wave choice is unsuitable.

This applies to:

  • Metal L1 / Metal L2
  • Shark Harm L1 / Shark Harm L2
  • Sync L1 / Sync L2

Compatibility rules

Metal

Works with:

  • Sine
  • Triangle Classic
  • SuperWave

Shark Harm

Works with:

  • Triangle Sharktooth
  • SuperWave

Sync

Works with:

  • Saw
  • Pulse
  • SuperWave

The script can announce a message such as:

  • Works with ...

This helps avoid the common problem of adjusting a parameter that appears inactive only because the wave family does not support it in the current context.

Practical Workflow Notes

The LJuno-116 interface becomes faster the more it is treated as a structural workspace rather than as a visual replacement for a front panel.

A good working rhythm is often:

  1. choose the page
  2. select the parameter
  3. use arrows for quick adjustment
  4. use PageUp or PageDown for broader movement
  5. use Enter for exact numeric edits when needed
  6. use Backspace to restore the current parameter if experimentation goes too far
  7. use Delete only when you want a full reset of the instrument state
  8. use Ctrl+C before risky experimentation when you want a complete recoverable snapshot
  9. use Insert when you want organized preset browsing, search, save, rename, delete, preview, and manual ordering

A few especially useful habits:

  • use Tab often to confirm the current parameter and value
  • use Backslash to re-center yourself on the current page or browser context
  • use the stored step widths to switch between precision work and fast broad movement
  • think of F8 and F9 as conditional pages that exist only when SuperWave is active on the corresponding layer
  • think of F11 as the bridge between the synth and its arpeggiator workflow
  • inside the browser, press Enter first to select a preset for movement, then use Up or Down to move it in the saved order

The interface is strongest when learned page by page rather than all at once.
